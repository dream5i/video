# SoraTK 竞品分析文档

测试日期：2026-04-23

## 1. 文档目的

本文档基于一次真实登录状态下的手动实测，目标是回答三个问题：

1. `soratk.com` 这款产品到底在做什么。
2. 它哪些功能已经形成了可用闭环，哪些地方还不稳定。
3. 我们在 `全新项目` 中应该借鉴什么、避免什么。

## 2. 结论摘要

SoraTK 不是单点型 AI 工具，而是一套面向电商短视频场景的 AI 生产平台。它的核心思路不是“直接帮你生成一条视频”，而是把做带货短视频这件事拆成一条可编排的生产链路：

`链接解析/去水印 -> 爆款复刻 -> 工作流编排 -> 角色与案例资产 -> 生成历史管理`

本次实测中，确认跑通或确认可用的能力如下：

| 模块 | 状态 | 结论 |
| --- | --- | --- |
| 首页 / AI商品视频工作台 | 部分验证 | 可输入提示词和选择模型，但 CTA 最终进入工作流画布，不是直接出片 |
| 去水印 | 已跑通 | 同一条抖音链接成功解析并产出无水印下载链接 |
| 爆款复刻 | 已跑通但不稳定 | 实际成功输出拆解结果，但上游分析能力存在供应商失败问题 |
| 工作流画布 | 已验证 | 可进入、可添加节点、可配置参数、可准备运行 |
| 带货案例 | 已验证 | 可浏览案例和提示词素材，但复制行为未完全稳定验证 |
| 生成历史 | 已验证 | 页面清晰，但本次未完成真实生成任务，因此无记录 |
| 角色工坊 | 部分验证 | 可见官方角色与上传入口，但未完成角色入库闭环 |
| 会员 / 积分 / 配置秘钥 | 已验证 | 商业化和供应商依赖关系非常清楚 |

附带结果：

- 本次实测使用了真实会员账号。
- 测试期间账号显示为 `PRO`。
- `爆款复刻` 流程共消耗了积分，测试后可见剩余积分为 `19`。

## 3. 竞品定位

### 3.1 产品定位

SoraTK 可以定义为：

`面向电商和带货团队的 AI 短视频生产操作台`

它不是只解决“生成视频”这一件事，而是覆盖了从素材获取、爆款拆解、脚本理解、工作流配置到资产沉淀的完整链路。

### 3.2 目标用户

从页面结构和功能命名推断，主要目标用户包括：

- 带货短视频操盘手
- 电商团队内容运营
- 小型广告制作团队
- 想快速复刻爆款结构的个体创作者

### 3.3 核心价值主张

它提供的不是一个模型能力，而是一整套“减少制作门槛、提高复用效率”的工作方式：

- 用链接快速拿到可用素材
- 用 AI 拆解爆款视频结构
- 用工作流把视频生产变成标准动作
- 用案例库和角色库沉淀可复用资产

## 4. 产品结构拆解

从实际行为来看，SoraTK 的产品结构可以拆成四层。

### 4.1 入口工具层

- 去水印
- 爆款复刻
- 首页提示词生成入口

这一层负责让用户快速带着一个需求进入系统，通常是“给我一个链接”或“我想做某个产品视频”。

### 4.2 生产中枢层

- 工作流画布
- 节点配置
- 全部运行 / 发布

这一层是整个平台真正的核心。首页、案例页和“做同款”入口，最终都在往工作流引擎导流。

### 4.3 资产沉淀层

- 带货案例
- 角色工坊
- 生成历史

这一层负责积累模板、角色、结果和经验，使平台不只是一次性工具，而是生产系统。

### 4.4 供应与商业化层

- 配置秘钥
- 会员体系
- 积分体系

这一层说明产品高度依赖第三方模型或供应商，并通过会员和积分控制使用成本。

## 5. 模块级实测分析

### 5.1 首页 / AI商品视频工作台

**实测结果**

- 页面提供提示词输入框、模型选项、视频条数和开始生成按钮。
- 可见模型包括 `Grok 3 10秒`、`Grok 3 20秒`、`Grok 3 6秒`、`Veo 3.1 Fast Geek BYOK`、`veo3.1 Fast`、`veo3.1 Quality`。
- 填写提示词并点击 `开始生成` 后，没有直接开始生成，而是跳转到工作流画布页面。

**价值判断**

- 首页承担“需求入口”作用。
- 真实生成逻辑并不在首页，而在工作流系统内。

**问题判断**

- `开始生成` 的文案会让用户预期“立刻出结果”，但实际动作是“进入空白工作流”。
- 这会造成明显的心理落差，尤其对新用户不友好。

### 5.2 去水印

**实测结果**

- 输入同一条抖音分享链接后，页面成功识别来源为 `抖音`。
- 页面给出 `无水印下载` 和 `备用线路` 两个可用结果。
- 该流程是本次最明确、最顺畅的闭环之一。

**价值判断**

- 这是一个非常强的流量入口型功能。
- 用户能在最短时间内感知价值，适合承担“获客第一步”。

**问题判断**

- 当前页面名称和能力表达基本清楚，没有明显结构性问题。

### 5.3 爆款复刻

**实测结果**

- 使用真实抖音链接完成过一次完整分析。
- 页面中途有进度停滞感，但最终成功输出拆解内容。
- 输出内容包括时间轴拆解、文案分析、卖点总结以及面向美国市场的本地化建议。

**价值判断**

- 这是平台最有竞争力的高价值模块之一。
- 它直接命中了“带货内容团队最想知道别人为什么爆”的核心需求。

**问题判断**

- 上游分析接口并不稳定，曾返回供应商失败错误。
- 这说明能力链条强依赖外部提供方，成功率和地域限制都会影响体验。
- 更重要的是，该功能会真实消耗积分，失败重试的容错成本较高。

### 5.4 工作流画布

**实测结果**

- 成功进入工作流画布，并打开模块面板。
- 可见模块包括 `开始节点`、`图片节点`、`视频节点`、`AI视觉大脑`、`批量下载`。
- 成功添加 `开始节点`，并看到完整配置表单，包括产品图、产品名称、比例、卖点、台词、图片风格、视频风格、批量数量和补充说明。
- 节点加入后，`全部运行` 与 `发布` 按钮变为可用。

**价值判断**

- 这是 SoraTK 最核心的底座能力。
- 它决定了平台是“模板工具”还是“生产系统”，而 SoraTK 明显在往后者走。

**问题判断**

- 首页和做同款入口都把用户带进了一个近乎空白的画布。
- 如果没有默认模板、预置链路或引导提示，用户会不知下一步做什么。

### 5.5 带货案例

**实测结果**

- 页面可正常浏览，支持按视频类型和产品分类筛选。
- 每个案例提供 `复制提示词` 动作。
- 复制动作在本次自动化验证中没有拿到完全可靠的结果，因此只能确认界面存在，不足以确认复制链路完全稳定。

**价值判断**

- 这是案例库和提示词灵感库的组合。
- 对新手非常有帮助，可降低“不会写提示词”的门槛。

**问题判断**

- 如果复制动作不稳定，案例库的即时转化价值会下降。
- 它容易沦为“只可浏览、难以复用”的展示区。

### 5.6 生成历史

**实测结果**

- 页面说明清楚，明确表示这里只管理已生成内容。
- 页面提示 AI 图片和视频历史只保留 `7天`。
- 由于本次没有完成一条真实生成视频任务，因此历史中没有新增生成记录。

**价值判断**

- 这是一个合理的后台管理页。
- 它有助于把生产行为沉淀成可检索资产。

**问题判断**

- 当前问题不在页面本身，而在前面生成入口与工作流入口的关系不够顺。

### 5.7 角色工坊

**实测结果**

- 页面可正常打开，可见官方预设角色以及上传入口。
- 页面显示当前保存数量上限，说明产品想让角色成为长期资产。
- 但本次没有成功完成“上传至角色库”的闭环验证。

**价值判断**

- 如果后续角色能进入视频流程，它会显著增强内容一致性与品牌人格稳定性。

**问题判断**

- 目前只能确认入口存在，不能确认它是否已经形成高可用闭环。

### 5.8 配置秘钥 / 升级会员 / 个人中心

**实测结果**

- 成功打开 `配置秘钥` 弹窗，看到多个供应商配置项。
- 成功查看会员页和个人中心，能够确认套餐、积分、权限和到期时间等信息。

**价值判断**

- 这说明平台对第三方模型供应能力有明显依赖。
- 它同时也说明产品支持较强的商业化和成本管控逻辑。

**问题判断**

- 供应商依赖意味着稳定性、地域可用性、成本波动都会成为产品风险。

## 6. 用户主流程推断

结合实际页面行为，可以把 SoraTK 的典型主流程理解为两条。

### 6.1 链接驱动型流程

`短视频链接 -> 去水印或解析 -> 爆款复刻 -> 进入工作流 -> 配置节点 -> 运行生成`

这条路径更适合“看到一个爆款，想快速复刻结构”的用户。

### 6.2 需求驱动型流程

`输入产品需求或提示词 -> 首页工作台 -> 进入工作流 -> 补充参数 -> 运行生成`

这条路径更适合“我已经知道我要做什么，只需要平台帮我生产”的用户。

## 7. 竞品优势

### 7.1 优势一：价值链完整

它没有停留在单个 AI 能力上，而是尝试覆盖从素材获取到成片生产的整条路径。

### 7.2 优势二：入口价值明确

去水印和爆款复刻都是很容易让用户快速理解并愿意尝试的功能，天然适合做增长入口。

### 7.3 优势三：工作流形态具备扩展性

一旦工作流和节点系统成熟，平台可以不断叠加新的能力，而不需要频繁重做前端结构。

### 7.4 优势四：资产化方向正确

案例库、角色库、历史页都在强化“复用”和“沉淀”，这比一次性生成工具更适合长期留存。

## 8. 竞品短板

### 8.1 短板一：入口承诺与实际动作不一致

`开始生成` 和 `一键做同款` 会让用户期待“马上得到结果”，但实际只是进入画布，这种落差会损伤体验。

### 8.2 短板二：核心高价值能力稳定性不足

爆款复刻虽然价值高，但上游接口不稳定，一旦失败，就会让用户对整个平台失去信心。

### 8.3 短板三：工作流对新用户不够友好

如果默认落在空白画布，系统就把“下一步如何搭流程”的认知负担交给了用户。

### 8.4 短板四：辅助能力闭环感偏弱

案例复制、角色上传等能力入口存在，但闭环验证感不够强，容易影响对产品成熟度的判断。

## 9. 对全新项目的借鉴建议

### 9.1 应该借鉴的方向

1. 先用一个高感知价值入口把用户拉进来，最适合的是 `链接解析` 或 `爆款拆解`。
2. 用一套统一工作流承接所有入口，而不是每个页面各自做一套逻辑。
3. 从第一天就考虑可沉淀资产，包括模板、案例、角色、历史与脚本。
4. 把成本控制放进产品结构里，而不是等到后面再补会员与积分系统。

### 9.2 应该避免的问题

1. 不要让首页 CTA 和实际动作不一致。
2. 不要默认把新用户丢进空白工作流。
3. 不要把高成本、高不稳定性的能力放在最脆弱的首次体验路径上。
4. 不要让“案例库”和“角色库”变成只看不转化的展示页。

### 9.3 更适合我们的首版做法

如果 `全新项目` 未来也做同类方向，建议首版先集中做一条最短闭环：

`短视频链接输入 -> 内容拆解 -> 自动生成脚本/镜头方案 -> 一键进入预填充工作流 -> 生成结果`

这条闭环比直接做一个大而全的平台更容易验证价值，也更适合快速迭代。

## 10. 最终判断

SoraTK 值得参考，但不适合照搬。

它真正值得学习的不是某个页面长什么样，而是它背后的产品方法：

- 用入口工具拿需求
- 用高价值分析建立信任
- 用工作流承接复杂生产
- 用资产库提高复用率
- 用会员与积分控制成本

对 `全新项目` 来说，最重要的不是“做一个像 SoraTK 的网站”，而是抽出它最有价值的主链路，做得更顺、更稳、更少认知负担。
