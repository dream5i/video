## 1. 这份文档解决什么问题

这份文档回答的是：

`哪些数据要留，留多久，怎么删，出问题后怎么恢复。`

小白版解释：

- 不是只管“存起来”
- 还要管“什么时候该删、删错了怎么办、炸了怎么救”

## 2. 当前阶段的数据分类

当前先把数据分成 6 类。

### 2.1 配置与密钥

例如：

- `.env`
- access token
- provider key
- 数据库连接串

规则：

- 不进入仓库
- 不进入外部模型
- 不进入普通日志

### 2.2 结构化业务事实

例如：

- Project
- AnalysisRun
- WorkflowDraft
- RenderRun
- RunStep

规则：

- 这是系统事实来源
- 以数据库为准

### 2.3 原始输入与源素材

例如：

- 用户输入的 URL
- brief
- 上传文件
- 抓取到的源视频

规则：

- 默认视为高敏或至少中敏
- 不做不必要的长期保留

### 2.4 中间产物与结果产物

例如：

- transcript
- OCR
- insight JSON
- 预览图
- 输出文件

规则：

- 允许按业务需要短中期保留
- 但必须有可清理策略

### 2.5 审计、日志与 trace

例如：

- request_id
- trace_id
- 审批记录
- review 证据

规则：

- 要能支撑排障和追责
- 但要脱敏

### 2.6 Prompt / provider 返回元数据

例如：

- prompt version
- model name
- capability
- latency / retry / cost

规则：

- 元数据默认可保留
- full raw response 默认不长期保存

## 3. 当前阶段的默认保留策略

下面这些是当前内部搭建阶段的第一版默认值。

| 数据类型 | 当前默认保留 |
| --- | --- |
| 临时文件 / 临时下载 / 临时转码缓存 | `7 天` 内清理 |
| 中间产物 | `30 天` 默认保留，之后进入清理候选 |
| 最终结果产物 | `30 天` 默认保留，后续按产品策略升级 |
| 结构化项目记录与运行记录 | `180 天` 默认保留 |
| 审计、发布、回滚证据 | `365 天` 默认保留 |
| provider raw response 全量原文 | 默认不长期保留；如为调试短期保留，建议 `<= 7 天` 且脱敏 |

说明：

- 这是当前阶段的工程基线
- 不是最终对外承诺
- 如果后面进入企业交付，要再结合合规要求升级

## 4. 当前默认删除策略

## 4.1 临时数据

策略：

- 到期自动清理
- 不需要人工逐条审批

## 4.2 项目级删除

当前建议流程：

1. 标记删除请求
2. 停止新 run
3. 删除对象存储中的源文件和派生产物
4. 删除或归档结构化记录
5. 保留最小审计 tombstone

小白版解释：

- 不是按一下按钮就所有东西瞬间消失
- 而是先锁住，再删数据，再留一个最小的“删过的痕迹”

## 4.3 高风险删除

以下删除默认视为高风险：

- 批量删除
- retention policy 修改
- 涉及审计记录删除
- 涉及 production 数据删除

要求：

- review pass
- 人工批准

## 5. 当前阶段的恢复目标

专业说法：

- `RTO`
  - Recovery Time Objective
  - 恢复时间目标
- `RPO`
  - Recovery Point Objective
  - 可接受数据回退点

小白版解释：

- RTO 是“多久恢复回来”
- RPO 是“最多能接受丢到多久之前”

## 5.1 当前环境目标

| 环境 | RTO 目标 | RPO 目标 |
| --- | --- | --- |
| `local` | 不承诺 | 不承诺 |
| `staging` | `<= 8 小时` | `<= 24 小时` |
| `production` 目标值 | `<= 4 小时` | `<= 1 小时` |

说明：

- `production` 目前还是目标值，不代表已经达到
- 在真正进入生产前，必须先验证恢复流程

## 6. 当前阶段必须保留的最小恢复能力

1. 数据库迁移失败能回退或前滚修复
2. 对象存储路径和结构化记录能对上
3. 能定位某次故障对应哪批变更
4. 至少能恢复最近一份可用数据快照

## 7. 备份与恢复基线

## 7.1 Local

- 不做正式备份承诺
- 只作为开发环境

## 7.2 Staging

- 进入 staging 前要有可执行备份
- 至少要能做一次真实 restore 演练

## 7.3 Production 目标

- 数据库快照和恢复方案独立存在
- 对象存储恢复路径明确
- 关键恢复步骤有 runbook

## 8. 当前阶段不建议长期保留的内容

- 未脱敏的 provider raw response
- 无业务必要的全文 transcript 原文
- 无业务必要的原始抓取文本
- 调试时产生的大量临时缓存

## 9. 当前阶段的阻断条件

出现下面任一情况，不应进入 staging 或 production 准备：

- 无法说明保留多久
- 无法说明谁来删
- 无法说明怎么恢复
- migration 没有回退或修复路径
- 对象存储和数据库记录没有对应关系

## 10. 下一阶段要把哪些东西工程化

- 删除任务 job
- 过期清理 job
- backup / restore 脚本
- retention 配置化
- 审计 tombstone 模型

## 11. 一句话结论

当前数据治理基线可以概括成：

`保留最少必要的数据，默认给中间产物设置清理期限，删除要走受控流程，恢复要先有目标再有动作。`
