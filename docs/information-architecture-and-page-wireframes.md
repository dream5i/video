## 1. 这份文档的目标

这份文档把 PRD 里的功能范围翻译成页面结构、路由建议、核心组件和低保真页面草图，目的是回答下面几个执行问题：

1. 首版到底需要哪些页面。
2. 每个页面上要放哪些关键信息和主操作。
3. 用户从进入系统到拿到结果，页面之间怎么流转。
4. 哪些地方必须避免掉进 `SoraTK` 那种“空白工作流”体验。

## 2. 结构原则

### 2.1 先结果，后配置

用户先看到分析结果和预填充方案，再做修改，而不是先进入空白编辑器。

### 2.2 页面尽量少

首版只保留能支撑主链路的页面，不为未来平台化过早铺太多导航。

### 2.3 主流程不能断

每一页都要有清楚的下一步动作，避免用户停在中间不知道该去哪里。

### 2.4 运行状态可见

任何异步任务都必须有明确状态页或状态区，不允许“点了按钮但不知道有没有在跑”。

### 2.5 桌面优先，移动端可用

首版核心编辑行为发生在桌面端，但移动端至少要支持查看分析、查看历史和看结果。

## 3. 首版信息架构

### 3.1 一级结构

首版建议只保留下面 5 个一级功能域：

1. `工作台`
2. `项目`
3. `运行状态`
4. `结果`
5. `历史`

### 3.2 页面树

```text
全新项目
├── 工作台首页
│   ├── 爆款链接入口
│   ├── 商品信息入口
│   └── 最近项目
├── 项目页
│   ├── 分析结果
│   ├── 脚本与镜头方案
│   └── 预填充工作流
├── 运行详情页
│   ├── 当前步骤
│   ├── 处理日志
│   └── 失败原因 / 重试
├── 结果页
│   ├── 结果预览
│   ├── 结果说明
│   └── 再次编辑 / 再次运行
└── 历史页
    ├── 项目列表
    └── 状态筛选
```

### 3.3 路由建议

```text
/                         工作台首页
/projects/new             新建项目入口
/projects/:projectId      项目总览，默认落在分析结果
/projects/:projectId/analysis
/projects/:projectId/workflow
/projects/:projectId/runs/:runId
/projects/:projectId/result
/history
```

说明：

- `projects/:projectId` 应该默认重定向或默认展示 `analysis`，因为分析结果是最容易建立信任的页面。
- `workflow` 不是空白开始，而是分析后的可编辑承接页。
- `runs/:runId` 独立出来，是为了异步任务状态更清楚，也方便后续支持多次生成。

## 4. 主导航设计

### 4.1 桌面端导航

左侧建议使用极简导航，只保留：

- `工作台`
- `历史`

项目内二级导航不放在全局侧边栏，而放在项目头部标签页：

- `分析`
- `工作流`
- `运行`
- `结果`

这样做的原因：

- 首版页面不多，左侧栏不需要过重。
- 项目内部是一个连续流程，适合用顶部标签强化顺序感。

### 4.2 移动端导航

移动端建议只保留底部 2 个入口：

- `工作台`
- `历史`

项目内部用顶部下拉或分段控件切换：

- `分析`
- `工作流`
- `结果`

## 5. 页面定义

### 5.1 工作台首页

### 页面目标

让用户在 10 秒内知道怎么开始，并且能看见最近项目，形成“继续做事”的感觉。

### 页面模块

#### A. 顶部区

- 产品标题
- 一句副标题：
  `从爆款链接到可执行短视频方案`

#### B. 主入口区

两个并列卡片：

- `粘贴爆款链接`
- `手动输入商品信息`

#### C. 最近项目区

- 最近 3 到 5 个项目
- 显示项目标题、状态、更新时间
- 点击后直接进入项目

#### D. 辅助说明区

- 简短说明平台做什么
- 不用长篇介绍

### 主按钮

- `开始分析`
- `创建项目`

### 空状态文案方向

- `给我一条爆款链接，我先帮你拆出来`
- `如果没有参考视频，也可以直接从商品卖点开始`

### 低保真草图

```text

| Logo                     从爆款链接到可执行短视频方案         |
|                                                              |
|  +--------------------+  +-------------------------------+   |
|  | 粘贴爆款链接        |  | 手动输入商品信息               |   |
|  | [ 输入框         ] |  | 商品名 [         ]            |   |
|  | [ 开始分析 ]       |  | 卖点   [         ]            |   |

| 最近项目                                                     |

| [ 项目B | 生成中   | 1小时前  ]                              |
| [ 项目C | 失败     | 昨天    ]                              |
+--------------------------------------------------------------+
```

### 5.2 分析结果页

### 页面目标

让用户第一时间看到“系统真的理解了这条内容”，并愿意继续进入工作流。

### 页面模块

#### A. 来源摘要

- 原始链接
- 来源平台
- 缩略图或首帧
- 项目标题

#### B. 结构拆解

- 开头 Hook
- 中段卖点展开
- 结尾 CTA

#### C. 关键洞察

- 目标人群推断
- 卖点列表
- 表达风格
- 节奏建议

#### D. 脚本草稿预览

- 只展示摘要
- 提供 `进入工作流继续编辑`

### 主按钮

- `进入工作流`
- `重新分析`

### 低保真草图

```text
+--------------------------------------------------------------+
| 项目标题                         [ 进入工作流 ] [ 重新分析 ]  |
|--------------------------------------------------------------|
| 来源：抖音  原始链接：xxxx                                    |
| 缩略图                                                     |
|--------------------------------------------------------------|
| 结构拆解                                                    |
| 1. Hook：前3秒用口味记忆点抓人                              |
| 2. 卖点：配料干净、适合孩子、口感清甜                       |
| 3. CTA：强调放心喝与品牌心智                                |
|--------------------------------------------------------------|
| 关键洞察                                                    |
| [ 目标人群 ] [ 卖点 ] [ 风格 ] [ 节奏 ]                     |
|--------------------------------------------------------------|
| 脚本草稿摘要                                                |
| “第一口就记住的，是很浓的梨香...”                           |
+--------------------------------------------------------------+
```

### 5.3 工作流页

### 页面目标

把分析结果转成“能改、能跑”的结构化工作流，但不让用户感觉自己在搭系统。

### 页面模块

#### A. 顶部信息栏

- 项目标题
- 当前版本
- 来源摘要
- 主操作按钮

#### B. 左侧脚本区

- 分段脚本卡片
- 每一段可编辑
- 支持新增或删除段落

#### C. 中间镜头区

- 镜头卡片
- 每张卡片包含：
  - 镜头目标
  - 画面说明
  - 时长
  - 字幕建议

#### D. 右侧设置区

- 风格设置
- 比例
- 旁白语气
- 节奏偏好
- 生成模型或生成路径

### 主按钮

- `保存草稿`
- `开始生成`

### 为什么不用空白节点图

首版这里应刻意避免直接做传统节点画布，原因是：

- 新用户不需要理解节点关系
- 我们的目标是推进主链路，不是训练用户搭流程
- 结构化卡片更适合快速编辑与后续前端实现

### 低保真草图

```text
+-----------------------------------------------------------------------+
| 项目标题                    版本 v1      [ 保存草稿 ] [ 开始生成 ]    |
|-----------------------------------------------------------------------|
| 脚本卡片            | 镜头卡片                     | 风格设置          |
|--------------------|------------------------------|------------------|
| 段落1              | 镜头1                        | 比例  9:16       |
| [ 文本可编辑 ]     | [ 画面说明 ]                 | 风格  清新真实   |
|                    | [ 时长 3s ]                  | 旁白  亲切       |
| 段落2              | 镜头2                        | 节奏  快          |
| [ 文本可编辑 ]     | [ 画面说明 ]                 | 模型  默认链路   |
|                    | [ 时长 4s ]                  |                  |
+-----------------------------------------------------------------------+
```

### 5.4 运行详情页

### 页面目标

让用户清楚知道系统现在跑到哪一步，并且在失败时有可操作反馈。

### 页面模块

#### A. 任务状态总览

- 当前状态
- 当前步骤
- 开始时间
- 预计剩余时间

#### B. 步骤列表

- 解析中

- 生成脚本
- 生成镜头
- 渲染中

#### C. 错误区

- 失败原因
- 建议操作
- `重试`

### 主按钮

- `查看结果`
- `重试`
- `返回工作流`

### 5.5 结果页

### 页面目标

让用户获得“这次工作真的沉淀下来了”的感觉，而不是看完一次就消失。

### 页面模块

#### A. 预览区

- 视频预览
- 封面图
- 结果状态

#### B. 结果说明区

- 本次使用的脚本版本
- 风格设定摘要
- 生成时间

#### C. 后续操作区

- 再次编辑
- 重新生成
- 导出

### 主按钮

- `再次编辑`
- `重新生成`
- `导出结果`

### 5.6 历史页

### 页面目标

让用户能快速回到之前做过的项目，并知道哪些值得继续。

### 页面模块

- 搜索
- 状态筛选
- 项目列表
- 空状态

### 列表字段建议

- 项目标题
- 来源类型
- 最近状态
- 更新时间

## 6. 页面流转规则

### 6.1 正常流转

```text
工作台首页
  -> 分析结果页
  -> 工作流页
  -> 运行详情页
  -> 结果页
  -> 历史页 / 回到项目
```

### 6.2 失败流转

```text
任意运行失败
  -> 运行详情页展示错误
  -> 返回工作流修正
  -> 重新运行
```

### 6.3 回访流转

```text
历史页
  -> 打开项目
  -> 默认进入上次最后有效页面
```

建议规则：

- 如果项目已经有结果，默认进入 `结果页`
- 如果项目只有分析，默认进入 `工作流页`
- 如果项目刚创建，默认进入 `分析页`

## 8. 页面状态设计

每个核心页面至少要考虑 4 种状态：

### 8.1 Loading

- 展示 skeleton
- 告诉用户系统正在做哪一步

### 8.2 Empty

- 首页无历史
- 历史页无项目
- 结果页还没有结果

### 8.3 Success

- 展示完整数据和明确下一步

### 8.4 Error

- 告诉用户失败点
- 提供重试或返回操作

## 9. 桌面与移动端差异

### 9.1 桌面端

桌面端适合完整编辑，因此：

- 工作流页使用三栏布局
- 分析页可用双栏或上下结构
- 结果页优先展示大预览

### 9.2 移动端

移动端目标不是完整编辑，而是“可查看、可简单改、可继续跑”：

- 首页入口改为纵向堆叠
- 工作流页改成分段折叠卡片
- 运行页保留步骤列表
- 结果页重点是预览和再次运行

## 10. 这份页面结构要避免的问题

### 10.1 不要像 SoraTK 一样让首页按钮通往空白画布

首页主按钮必须通往：

- 分析中
  或
- 分析结果

而不是直接丢进一个等待用户自己搭的系统页面。

### 10.2 不要让分析结果和工作流割裂

分析结果必须能一键转成工作流，避免用户重新填写相同内容。

### 10.3 不要把运行状态藏起来

长耗时任务要独立有状态展示，而不是只在按钮上转圈。

### 10.4 不要让历史页只是死列表

历史页的价值在于继续编辑和继续跑，而不是只做记录。

1. `技术方案与系统架构初稿`
2. `首页 + 分析页 + 工作流页` 的实际前端原型
