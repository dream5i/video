## 1. 这份文档解决什么问题

这份清单用来回答：

`哪些内容绝不能送进外部模型上下文，哪些内容即使本地可读，也不应该被 AI 当作普通开发语料。`

这份文档的目标不是“尽量少喂”，而是：

- 先把绝对禁区写死
- 再把允许替代方案写清楚
- 避免因为高权限误把敏感内容送入模型

## 2. 总原则

- `能读` 不等于 `能喂`
- `本地高权限` 不等于 `可外发敏感上下文`
- 优先给 AI 提供：
  - 摘要
  - 脱敏片段
  - 合成样例
  - 伪造 fixture

## 3. 一律禁止进入外部模型上下文的内容

### 3.1 凭据与密钥

- `.env`
- `.env.*`
- `*.pem`
- `*.key`
- `id_rsa*`
- `id_ed25519*`
- `secrets/**`
- 云服务访问密钥
- 第三方平台 token
- 数据库连接串

### 3.2 生产环境与运维敏感信息

- 生产数据库导出
- 生产环境配置
- 线上故障应急手册
- 运维访问凭据
- 内网域名与专有拓扑细节

### 3.3 客户与业务敏感数据

- 客户 PII
- 商家后台导出
- 订单原文
- 未脱敏运营报表
- 真实交易数据
- 真实视频素材中带敏感身份信息的原始片段

### 3.4 法务与受限文档

- 合同正文
- 商业条款附件
- 法务评审意见
- 未公开融资或合作文件

### 3.5 来源受限的第三方代码

- 未获授权的第三方仓库代码
- 与许可证不兼容的拷贝片段
- 不能确认来源的大段代码

## 4. 对我们项目的 repo 级敏感路径建议

下面这些路径建议默认加入 exclusion / deny-read 体系：

- `./.env`
- `./.env.*`
- `./secrets/**`
- `./docs/security/**`
- `./docs/review/**`
- `~/.ssh/**`

说明：

- `docs/security/**`
  - 不是因为这里的文档一定机密
  - 而是为了避免安全边界与应急说明被随手带入上下文
- `docs/review/**`
  - 便于把审查模板和审批说明当治理资产看待

## 5. 可以替代直接喂原文的做法

当任务必须借助 AI，但原始内容不能直接提供时，优先使用：

- 结构化摘要
- 人工脱敏后的片段
- 合成测试数据
- 固定格式的 schema
- 最小可复现场景

例如：

- 不给真实订单原文，改给字段级假数据
- 不给真实商家后台导出，改给列结构和示例行
- 不给生产报错原文，改给已脱敏 stack trace

## 6. Cloud Agent 与 Local Agent 的边界

### 6.1 允许进入云端 agent 的内容

- 公共文档
- 已脱敏项目文档
- 非生产 stub 数据
- 合成 fixture
- 不含敏感字段的代码片段

### 6.2 只允许本地受控处理的内容

- 密钥
- 本地缓存中的会话残留
- 真实客户数据
- 真实商家经营数据
- 运维上下文
- 任何无法确认是否已脱敏的输入

## 7. 操作前检查

在把上下文交给外部模型前，先问 5 个问题：

1. 这里面有没有密钥、token、连接串？
2. 这里面有没有客户、商家、订单、交易或身份信息？
3. 这里面有没有生产环境、运维、审计、法务材料？
4. 这段代码或文档的来源和许可证能不能确认？
5. 这个任务能不能改成摘要、脱敏片段或合成 fixture？

只要有一项不能确认，就不要直接喂。

## 8. 与配置文件的关系

这份文档对应的可执行模板包括：

- `.codex/requirements.example.toml`
- `codex/rules/default.rules`

后续如果进入正式企业部署，还应同步到：

- managed requirements
- content exclusion 配置
- 仓库 opt-out 或 cloud agent policy
- 审计与 review 流程
